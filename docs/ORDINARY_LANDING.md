# Ordinary constrained landing experiment

`landing_rh` and `landing_mpc` are complete OCPs in separate files. They use the shared parameter defaults and external constant-acceleration predictor. They contain no CTCS interval rows, violation integrators, state triggers, staging conditions, or trigger-dependent costs.

Landing limits apply throughout the horizon and at its terminal node: 0.75 m/s relative speed, 0.95 degrees tilt, 0.019 rad/s body angular speed, 15 degrees glideslope with the existing 0.1 m apex offset, 30 degrees LOS, and the altitude floor. Speed, angular rate, tilt, glideslope, and LOS use native SOC rows; actuator bounds and the floor use ordinary inequalities. Quaternion-dependent rows normalize attitude. The independent start check evaluates these same physical limits.

The RH arm retains variable time steps and full-state replay; MAVROS sends position, velocity, and yaw. The MPC arm retains the fixed grid, actuator-rate lag, direct thrust/body-rate output, 50 Hz feedback, and existing saturation/slew limits. Controller tuning, solver settings, and physical limits match the corresponding saved MC1 settings. The ordinary objective is unconditional landing. Initialization supplies a speed-limited descent and bounded attitude/rate seed.

Run the existing campaign script with `--start cone`, one trial, zero estimate noise, and a `profile_landing_rh_sitl.yaml` or `profile_landing_mpc_sitl.yaml` profile. Cone preparation follows the target 1.85 m above its landing point. High-curvature motion uses a reference acceleration/jerk limiter derived from the same landing limits, allowing a feasible initial state without weakening them. The measured start must satisfy all landing limits for 0.5 seconds; preparation continues until the first planner command. Preparation times out after 30 seconds and first-plan acceptance is checked after 15 seconds; a missing accepted plan records initialization failure after clean teardown. Cases run sequentially and stop on failure. A successful landing requires the planner's touchdown handoff and PX4 disarm, followed by clean teardown.

Bags, solver CSVs, extracted state CSVs, input profiles, and results belong together under `logs/`. Enable `COMANDO_BUILD_ANALYSIS` to build `constraint_audit`; run `support/scripts/analyze_direct_mpc.py CAMPAIGN --physical --audit-bin PATH` under ROS1 to audit accepted nodes, 1 ms interval propagation, continuous rollouts, and measured states. The measured audit starts at the first ordinary controller output and ends at touchdown handoff or policy expiry; it excludes subsequent disarm/ground-contact dynamics. Horizon durations overlap and are reported as sums, not elapsed flight time. Initial violations are reported separately.

Ordinary node constraints do not certify continuous-time or plant feasibility. The existing aggregate solver-error acceptance threshold is also not an independent physical feasibility certificate. The cone-start experiment changes both initial geometry and the formulation, so comparisons with the original CTCS engagement runs are diagnostic rather than a controlled CTCS ablation.
